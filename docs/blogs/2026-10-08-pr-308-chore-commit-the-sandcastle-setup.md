# chore: Commit the Sandcastle setup

- **Release tag:** `v0.1.117`
- **Source PR:** [#308](https://github.com/mpaulosky/Articles/pull/308)

## PR description

### Why

`.sandcastle/` and the `package.json` that installs `@ai-hero/sandcastle` were never committed, so a fresh clone couldn't run Sandcastle and prompt changes went unreviewed. Committing it surfaced problems with the template's workflow: agents that read public issue text held an Issues-write GitHub token, untrusted comments reached the agents, a merger agent merged branches locally and closed issues outside the PR flow, the sandbox had no .NET SDK, and the prompts asked for `npm` scripts and `RALPH:` commits this repo doesn't have.

### What changed

- **GitHub stays on the host.** The sandbox gets no GitHub token and no `gh`. The host reads the open `Sandcastle` issues with its own `gh` auth and keeps only issues opened by, and comments written by, the owner, members and collaborators (`lib/github.mts`). Agents get the issue in their prompt. `main.mts` refuses to start while `.sandcastle/.env` sets `GH_TOKEN` or `GITHUB_TOKEN`.
- **One draft PR per issue.** Each issue is built in its own sandbox (`lib/build.mts`): the implementer works it, the host runs `.sandcastle/check.sh` (the solution build and every test project that doesn't need Docker), and the reviewer refines the change and ends with a structured <code>&#60;verdict&#62;</code> (approve/reject, fail-closed). The host checks again if the reviewer committed. Only an approved, green branch is pushed, as a draft PR that says `Fixes #n`; anything else gets a comment on the issue. The local merge phase, `merge-prompt.md` and the closing of issues are gone. Issues with an open PR are held back, and a round that opens no PR stops the loop.
- **Branches:** bugs get <code>fix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code> (not `hotfix/`), and existing `feature/`, `fix/` and `hotfix/` branches on origin are reused.
- **Sandbox image:** installs the .NET 10 SDK and pnpm through Corepack. The sandbox installs with `pnpm install --frozen-lockfile`. The root `package.json` pins `pnpm@12.6.0` and blocks npm, like `src/Web`.
- **Prompts:** commits follow `git-commit-instructions.md` (no `RALPH:`), the reviewer diffs against <code>&#123;&#123;BASE&#95;BRANCH&#125;&#125;</code> (`origin/main`; Sandcastle sets <code>&#123;&#123;TARGET&#95;BRANCH&#125;&#125;</code> to the sandbox's own branch and refuses an override), and `CODING_STANDARDS.md` points at the repo's instructions.
- **Tests in the gate and CI:** `pnpm run test:sandcastle` type-checks `.sandcastle/` and runs its tests. `.github/ci/gate-checks.sh` (pre-push) and `.github/ci/prepare.sh build` (CI's Build Solution job) run it when `.sandcastle/` or the root package files change.

### Verification

- `pnpm run test:sandcastle`: `tsc` clean, 52 tests pass (trust filtering, verdict parsing, the build pipeline's publish and stop paths, branch names against `scripts/check-branch-name.sh`, PR titles against `scripts/check-pr-title.sh`, prompt placeholders).
- `docker build` of `.sandcastle/Dockerfile` succeeds, and `.sandcastle/check.sh` passes inside the image (.NET 10.0.401 SDK; the AppHost, Integration and E2E projects skipped as needing Docker).
- The pre-push gate (`scripts/gate.sh`) passed, and `.github/hooks/tests/pre-push.test.sh` passes.
