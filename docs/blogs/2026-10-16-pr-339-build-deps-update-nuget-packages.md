### Why

Several centrally managed package versions had fallen behind their latest stable minor and patch releases, and `Aspire.Hosting` (13.4.6) had drifted from the other Aspire packages and the AppHost SDK (13.6.1).

Held back:

- **StackExchange.Redis 3.x** (3.4.5): `Aspire.StackExchange.Redis.*` 13.6.1 is compiled against 2.13.17, so 3.x risks runtime `MissingMethodException`s that the tests might not catch. The entry moves to 2.13.17, the version Aspire resolves.
- **MessagePack 3.x**: stays on 2.5.307, the security pin for Aspire's transitive 2.x dependency (GHSA-qhrr-8q5h-9q3h). 2.5.307 is the newest 2.x.
- **Aspire.Hosting.NodeJS** stays at 13.4.6. The package was renamed `Aspire.Hosting.JavaScript`, and nuget.org's newest listed NodeJS version is 9.5.2, so it can't be aligned at 13.6.1. Moving to `Aspire.Hosting.JavaScript` 13.6.1 wouldn't help either. Only `Directory.Packages.props` lists the package: no project references it and the AppHost calls no Node or JavaScript hosting API, so restore never resolves this version and there's nothing to switch. The unused entry can be removed in a separate cleanup.
