## fix(scripts): Delete squash-merged branches in squad branch cleanup

- **Release tag:** `v0.1.86`
- **Source PR:** [#236](https://github.com/mpaulosky/Articles/pull/236)

### PR description

## What changed
`scripts/squad/cleanup-squad-branches.sh`:
- **Verifies PR-merged branches before deleting them.** A branch whose PR merged now counts only if its local tip is the merged PR's head, or an ancestor of it (checked with the GitHub compare API, `repos/{repo}/compare/{tip}...{head}` returning `ahead` or `identical`).
- **Deletes verified branches with `git branch -D`.** `-d` always refuses squash-merged branches.
- **Skips branches with commits that never reached their PR**, and says why: `PR merged, but the local branch has commits not in it; review, then 'git branch -D'`.
- **Leaves orphans unchanged.** They still use `-d`, so they survive `--apply` unless `--force-local` is passed.
- **Hides Git's own "Deleted branch …" line**, so only the script's messages print.

## Why
A local `--apply` run deleted nothing: all 23 eligible branches failed with `use --force-local for unmerged branches`. PRs here are squash-merged, so a merged branch's commits are never on `main`, and `-d` refuses every one. The only way round it was `--force-local`, which also force-deletes unmerged orphans that exist nowhere else.

The nightly CI run isn't affected. It runs on a fresh checkout with no local branches, and its last run found 0 eligible.
