# chore(sandcastle): Rename the sandbox gate to sandbox-gate.sh

- **Release tag:** `v0.1.143`
- **Source PR:** [#376](https://github.com/mpaulosky/Articles/pull/376)

## PR description

_Requested by **Matthew** · [project thread](https://claude.ai/code/project/chan_01M4TRjuaTvMLM1jqeNd9KNs?thread=cmsg_01M4TRjuaTvMLM1jqeNd9KNsLoaosm8ysUAJsisbA6Aheg)_

### Why

The repo-ci-baseline Template now owns `.sandcastle/check.sh` as Sandcastle's check for the local gate. This repo uses its own `.sandcastle/check.sh` as the
Docker-free sandbox gate, so `apply.sh` keeps the repo's copy and reports a conflict. The Template's `references/sandcastle.md` (steps 8 and 9) says to rename
the gate to `.sandcastle/sandbox-gate.sh` in a PR that merges before the next re-Apply. This is that PR, ahead of the November Baseline Rollout.

### What changed

- `.sandcastle/check.sh` is renamed to `.sandcastle/sandbox-gate.sh` (contents unchanged), and `GATE_COMMAND` and `GATE_SCRIPT` in `.sandcastle/lib/repo-config.mts` name it.
- The role prompts (`review-prompt.md`, `roles/follow-up.md`, `roles/gate-fixer.md`) name the new file, so Sandcastle keeps working until the re-Apply replaces them.
- `roles/shared-rules.md` says that a role prompt's `scripts/gate.sh` means `.sandcastle/sandbox-gate.sh` in the sandbox, as TicketManager's does, so the Template's prompts work after the re-Apply.
- `shared-rules.md` and the `repo-config.mts` comment now say what the gate actually runs: the build, the Docker-free tests and Sandcastle's tests, with no lints.
- New `.sandcastle/repo-scripts.test.mts` pins the gate's name, that its file is committed, that `CHECK_PATHS` covers it, and the `shared-rules.md` note.
  It doesn't require `check.sh` to be absent, since the re-Apply writes the Template's `check.sh` beside the gate.

### Verification

- `apply.sh --dry-run` against this branch reports no conflicts. It still lists `.github/workflows/sandcastle-tests.yml` as a leftover the Template doesn't carry, which is left for the re-Apply.
- `scripts/gate.sh` passes (the pre-push hook ran it), including `pnpm run check:sandcastle` and the E2E tests.
- The local pre-push review ran 3 rounds; the last found nothing.

### Review notes

The local review raised these and they were accepted, not changed:

- .sandcastle/lib/repo-config.mts:81: Once this merges, a Sandcastle branch or PR cut before the rename fails the host gate (no sandbox-gate.sh at its head) until main is merged into it, and is handed back as sandcastle:needs-human. Accepted: Matthew accepted 2026-11-18: no open PR or non-main branch exists in the repo, so no Sandcastle branch predates the rename; any later one fails closed until main is merged in.
