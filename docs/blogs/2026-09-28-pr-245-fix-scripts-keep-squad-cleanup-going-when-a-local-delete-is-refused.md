## fix(scripts): Keep squad cleanup going when a local delete is refused

- **Release tag:** `v0.1.88`
- **Source PR:** [#245](https://github.com/mpaulosky/Articles/pull/245)

### PR description

## Summary

Fixes a bug added in #238: a local `--apply` run **aborted** at the first local branch that `git branch -d` refused to delete.

`deleted=$(git branch -d … && echo yes)` returns non-zero when the delete is refused. Under `set -euo pipefail`, that exited the script with status 1, with no message, before any remote deletions. An old, unmerged local orphan (without `--force-local`) was enough to trigger it. This broke local cleanup, including the `squad-branch-cleanup` skill. The nightly GitHub job was unaffected, because a fresh checkout has no local orphans.

Found by Copilot on mpaulosky/TicketManager#59, and reproduced locally. Refs #240.

## Change

The delete command now runs as the `if` condition, so a refusal prints `failed to delete local … (use --force-local …)` and the run carries on.

## Tests

A new case has an old local orphan that `git branch -d` refuses, alongside an old remote-only orphan. It checks that the run exits 0, reports the refusal, keeps the local branch, and still deletes the remote orphan. Before the fix, 3 of its checks failed; now all **27/27** pass, and `shellcheck` is clean.
