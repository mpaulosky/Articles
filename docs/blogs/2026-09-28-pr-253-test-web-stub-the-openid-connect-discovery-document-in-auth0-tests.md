## test(web): Stub the OpenID Connect discovery document in Auth0 tests

- **Release tag:** `v0.1.91`
- **Source PR:** [#253](https://github.com/mpaulosky/Articles/pull/253)

### PR description

Closes #243

## Problem

`Login_WhenAuth0IsConfigured_ChallengesTheAuth0Scheme` and `Logout_WhenAuth0IsConfigured_SignsOutOfAuth0` point Auth0 at `example.auth0.com`, which isn't a real tenant. Before redirecting, the OpenID Connect handler downloads `https://example.auth0.com/.well-known/openid-configuration` through its `ConfigurationManager`. Whenever that request fails, the tests get **500** instead of **302** (IDX20803), as in #238's CI run 36366185186.

## Change

`CreateFactory` post-configures the Auth0 scheme (`Auth0Constants.AuthenticationScheme`) with a `StaticConfigurationManager<OpenIdConnectConfiguration>` that holds the issuer, authorize endpoint and end-session endpoint on the configured domain. The handler gets the document directly and makes no network call. The existing assertions (`302`, `Location.Host == "example.auth0.com"`, `/authorize`) are unchanged.

Setting `options.Configuration` isn't enough on its own: ASP.NET Core only wraps it in a static manager during its own post-configure step, which has already run by the time the test's `PostConfigure` does.
