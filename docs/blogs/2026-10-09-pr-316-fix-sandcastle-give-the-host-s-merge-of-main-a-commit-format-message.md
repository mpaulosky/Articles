# fix(sandcastle): Give the host's merge of main a commit-format message

- **Release tag:** `v0.1.120`
- **Source PR:** [#316](https://github.com/mpaulosky/Articles/pull/316)

## PR description

### Why

This is a follow-up to #314, for the one Claude Review thread still open when #314 merged.

Since #314, the host merges `origin/main` into an issue branch before checking it. The merge used git's default message, <code>Merge remote&#45;tracking branch &#39;origin&#47;main&#39; into &#60;branch&#62;</code>. `review-prompt.md` tells the reviewer to check commit messages against `.github/instructions/git-commit-instructions.md` and to approve only when nothing is left unfixed. So a reviewer could reject an otherwise good change whenever main had moved. It could also rebase the merge away to fix the message, which undoes the reason for the merge.

### What changed

- The host's merge commit is now `chore: Merge origin/main`, which follows the repository's commit format. Its body is `Brings the branch up to date with origin/main before it's checked.` The message leaves the branch name out entirely, so a long slug can't push any line past 72 characters.
- `review-prompt.md` says that a merge commit from <code>&#123;&#123;BASE&#95;BRANCH&#125;&#125;</code> belongs to the host. The reviewer shouldn't judge it, rewrite it or drop it.

### Verification

- `pnpm run test:sandcastle`: the type check and 78 tests pass. The merge test now checks the message, and that each of its lines is 72 characters or fewer.
- `scripts/check-pr-title.sh` accepts `chore: Merge origin/main`.
- The pre-push gate passed.
