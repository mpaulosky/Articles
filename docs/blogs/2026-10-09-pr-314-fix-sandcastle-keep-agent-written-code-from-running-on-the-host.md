# fix(sandcastle): Keep agent-written code from running on the host

- **Release tag:** `v0.1.119`
- **Source PR:** [#314](https://github.com/mpaulosky/Articles/pull/314)

## PR description

### Why

This addresses the Claude Review findings on #308, the Sandcastle redesign where the host does all GitHub work and opens one PR per issue.

The most serious finding was that the host pushed from the agent's worktree. Git therefore ran that branch's own `.github/hooks/pre-push`, `scripts/gate.sh` and test code on the host, with the user's gh auth, the Docker socket and the home directory. Agents can edit all of these files. There were two more paths to the same result. Sandcastle mounts the shared `.git` directory read-write into every sandbox, so an agent could set a command in `.git/config` (`core.fsmonitor`, a credential helper). Git also finds its config through `commondir` files, in `.git` itself and in each worktree's directory, and a worktree finds its directory through its `.git` file. Agents can write all of these, and pointing any of them at a directory of the agent's making makes a host git command read config the agent wrote.

### What changed

- **No git hook runs on the host, and host git reads only this repository's config.** Before any git command or agent runs, `main.mts` calls `protectHostGit()` (`lib/host-safety.mts`). It sets `core.hooksPath=/dev/null` through `GIT_CONFIG_*` and pins `GIT_COMMON_DIR` to the repository's `.git`, which outranks any `commondir` file. Both apply to every git command the process starts, Sandcastle's included. Sandcastle refuses to start if `.git/commondir` exists. The sandbox still runs `.sandcastle/check.sh`, and CI runs the full suite on the PR. The host no longer uses the sandbox's Linux `node_modules` either.
- **`.git/config` and `.git/hooks` are read-only in every sandbox.** They're mounted read-only over Sandcastle's read-write `.git` mount, for the planner and the builders alike. Agents can still commit.
- **The host runs git and gh only in the main checkout, never in a worktree.** It counts commits by ref. It pushes the exact commit the check passed on, as <code>&#60;sha&#62;&#58;refs&#47;heads&#47;&#60;branch&#62;</code>, with hooks off. Sandcastle still runs git in a worktree when it reuses or closes one. Before it does, the host checks that the worktree still points at this repository. If it doesn't, the host leaves the worktree for a person to look at. `host-safety.mts` documents what's left: a worktree's own HEAD and index can be redirected, which runs nothing unless `extensions.worktreeConfig` is on.
- **Main is merged into the branch** inside the sandbox before the first check. A reused branch, or one that main moved past during the build, is then checked and reviewed as it would merge. A merge conflict stops the issue with a comment.
- **The check runs again whenever the reviewer moves HEAD**, not only when it adds commits.
- **Fork PRs are ignored.** Open PRs count only if `isCrossRepository` is false, both when holding issues back and when looking for an existing PR.
- **Each picked issue is built once.** An issue the planner lists twice now runs one pipeline (`lib/plan.mts`).
- **PR titles lose trailing spaces** along with the closing period, so `add search .` becomes `feat: Add search`.
- **Only standard branch names are reused.** `review-prompt.md` passes <code>&#123;&#123;BRANCH&#125;&#125;</code> to a shell command in the sandbox.
- **Prompt-only PRs now run the Sandcastle tests.** Detect Changes counts every `.md` file as docs, so a PR that changed only `.sandcastle/*.md` skipped Build Solution, and with it the prompt tests. `detect_changes.py` is Owned by the Template, so a new repo workflow, `sandcastle-tests.yml`, covers that case. Build Solution still runs the tests through `prepare.sh` for everything else.

I also checked one suspicion and ruled it out. Sandcastle 0.12.0 marks the template's `` !`…` `` blocks with `\x01` before it fills <code>&#123;&#123;&#8230;&#125;&#125;</code> arguments, and it strips `\x01` from argument values. It only runs marked blocks, so an issue title or body that contains `` !`cmd` `` stays text.

### Verification

- `pnpm run test:sandcastle`: the type check and 78 tests pass. New tests cover:
  - the hooks override, against a real repository with a control commit that does run the hook
  - the read-only mounts
  - a planted `.git/commondir` naming a config that sets `core.fsmonitor`, with a control run without `GIT_COMMON_DIR` that does run it
  - worktree link tampering: a redirected `.git`, a redirected `commondir`, and a symlinked directory
  - the merge, including a conflict
  - a re-check after HEAD moves without new commits
  - pushing the checked commit
  - fork PR filtering
  - the deduplicated picks
  - titles with trailing spaces
  - non-standard branch names
- Docker by hand: with the same mounts, a container can still commit to a worktree branch. Writing `.git/config` fails with `Resource busy`, and writing to `.git/hooks` fails with `Read-only file system`.
- actionlint, zizmor, yamllint and shellcheck pass on the changed CI files, and the pre-push gate passed.
