## chore(web): Stop committing the generated app.css

- **Release tag:** `v0.1.99`
- **Source PR:** [#270](https://github.com/mpaulosky/Articles/pull/270)

### PR description

Every Tailwind bump from Dependabot leaves the committed `src/Web/wwwroot/app.css` stale: the lockfile moves on, but the CSS in git is still the old build. Each local build then regenerates the file and dirties the tree, which the pre-push gate refuses. CI never notices, because it regenerates the file too.

The build already produces `app.css` on every run, CI included. So it's now untracked and ignored, as in atelier-store, mpaulosky/TicketManager#92 and mpaulosky/IssueManager#220.

## Keeping `@Assets["app.css"]` working on a clean checkout

`wwwroot/**` is collected when the project first loads, before `app.css` exists. Two changes stop a clean build from leaving it out of the static-asset manifest:
- `TailwindBuild` now runs before `BeforeBuild` (it ran before `Build`);
- the target adds the generated file to `@(Content)` right after creating it.

## Validation

- A build with no `bin/`, `obj/`, `node_modules/` or `app.css` now lists `app.css` in `staticwebassets.build.json`.
- The pre-push gate passed (build and every test project).

**For existing clones:** after pulling, git deletes the local `app.css`, and the next build recreates it.
