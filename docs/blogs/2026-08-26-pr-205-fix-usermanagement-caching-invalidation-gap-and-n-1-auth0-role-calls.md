## fix: UserManagement caching invalidation gap and N+1 Auth0 role calls

- **Release tag:** `v0.1.71`
- **Source PR:** [#205](https://github.com/mpaulosky/Articles/pull/205)

### PR description

## Summary
- Removes `InvalidateRolesAsync`, which was dead code — no handler in this app mutates the Auth0 roles catalog, so it was never meaningfully stale.
- Fixes the N+1 Auth0 Management API call pattern in `GetUsersWithRolesQuery` by fanning out per-user role fetches with a bounded, appsettings-configurable concurrency (`Auth0:Management:RolesFetchConcurrency`, default 5) instead of one sequential call per user.
- Switches `Auth0ManagementApiClientFactory` from a manual per-call OAuth token exchange to the Auth0 SDK's `ClientCredentialsTokenProvider`, cached as a singleton so the access token is reused/auto-refreshed across requests instead of re-exchanged every call.
- Adds research notes (`docs/research/2026-08-25-issue-151-usermanagement-caching-solutions.md`) documenting the Auth0 Management API constraints (no bulk users+roles endpoint outside Organizations, documented rate limits) behind these choices.
