### PR description

## What changed
`GetMetadataAsync_FromLinkedWorktree_UsesWorktreeRepositoryOrigin` now saves, clears and restores `REPOSITORY_URL` alongside `GITHUB_REPOSITORY_URL` and `GITHUB_REPOSITORY`. The comment now says "All three variables".

## Why
This follows up a review comment on #228. `GetOriginUrlAsync` checks `GITHUB_REPOSITORY_URL ?? REPOSITORY_URL` before it looks for the git repo (`src/Web/Services/GitHubMetadataProvider.cs:99-100`). If `REPOSITORY_URL` was set, the provider skipped that search.

The effect was a spurious test **failure** rather than a false pass. The stubbed GitHub API only answers for the fake worktree repo, so the assertions fail whenever another origin is used. Either way, the test should control every input that decides which path the code takes.
