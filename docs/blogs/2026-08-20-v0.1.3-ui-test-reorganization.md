## Overview

Version 0.1.3 focuses on improving test organization and removing unnecessary demo code. This release moves UI component tests to a dedicated bUnit test project and removes the Counter demo component that was part of the initial Blazor template.

## What's New

### UI Test Reorganization

- **PR #18**: Reorganize UI tests and remove Counter demo
  - Created dedicated `Web.UI.Tests` project for bUnit tests
  - Moved component tests from `Web.Tests` to `Web.UI.Tests`
  - Configured bUnit testing infrastructure
  - Removed Counter demo component and associated tests
  - Improved test project separation of concerns

### Test Project Structure

The new test organization:

```
tests/
├── Web.Tests/              # Integration and unit tests
│   ├── Controllers/
│   ├── Services/
│   └── ...
├── Web.UI.Tests/           # UI component tests (bUnit)
│   ├── Components/
│   │   ├── ArticleListTests.cs
│   │   ├── CategoryListTests.cs
│   │   └── ...
│   └── GlobalUsings.cs
├── Domain.Tests/
├── Architecture.Tests/
└── AppHost.Tests/
```

## Technical Details

### Project Separation Rationale

**Before**: Mixed test concerns in `Web.Tests`
- Integration tests (API endpoints)
- Component tests (Blazor UI)
- Service tests
- Difficult to run tests selectively

**After**: Clear separation
- `Web.Tests`: API, services, middleware
- `Web.UI.Tests`: Blazor components only
- Can run component tests independently
- Cleaner test execution filtering

### bUnit Test Infrastructure

The dedicated UI test project provides:

```csharp
public class ArticleListTests : TestContext
{
    [Fact]
    public void Should_Display_Articles_When_Loaded()
    {
        // Arrange
        var articles = CreateTestArticles();
        Services.AddSingleton<IArticleRepository>(
            new MockArticleRepository(articles));

        // Act
        var cut = RenderComponent<ArticleList>();

        // Assert
        cut.FindAll(".article-item").Count.Should().Be(3);
    }
}
```

### Counter Demo Removal

Removed boilerplate files:
- `Components/Pages/Counter.razor`
- `Components/Pages/Counter.razor.cs`
- `Web.Tests/Components/CounterTests.cs`
- Navigation menu link to Counter
- Counter route registration

This cleanup removes ~150 lines of demo code that served no purpose in the Articles application.

## Migration Notes

For developers working on existing branches:

1. Component tests moved from `Web.Tests/Components/` to `Web.UI.Tests/Components/`
2. Add reference to `Web.UI.Tests.csproj` in solution
3. Remove any Counter-related code from custom branches
4. Update test runners to include new test project
