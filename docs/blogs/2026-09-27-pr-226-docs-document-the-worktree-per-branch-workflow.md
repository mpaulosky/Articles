## docs: Document the worktree-per-branch workflow

- **Release tag:** `v0.1.81`

### PR description

## What changed
- **`docs/CONTRIBUTING.md`**: each new branch now goes in its own git worktree under `../Articles-worktrees/<branch-with-dashes>`, branched from `origin/main`. The main checkout stays on `main`, so new work can start while an earlier PR is still in CI, auto-merge, or waiting on its release-blog PR. The guide also covers:
  - `git push -u origin HEAD`, because a branch created from `origin/main` tracks `origin/main` until it has its own upstream
  - turning on auto-merge with `gh pr merge --auto --squash` when the workflow doesn't
  - removing the worktree and branch after a squash merge, where `git branch -D` is needed because `-d` refuses
- **`src/Web/Services/GitHubMetadataProvider.cs`**: fixes a bug this workflow exposed. `FindGitRoot` only looked for a `.git` *directory*, but in a linked worktree `.git` is a *file*. Inside a worktree the provider found no repo and returned no metadata, so `FooterUsesGitHubReleaseMetadataWhenBuildInfoIsPlaceholder` failed and the footer fell back to build info.
