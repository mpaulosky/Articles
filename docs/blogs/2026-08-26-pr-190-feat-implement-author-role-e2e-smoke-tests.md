## Summary
- Implements the Author-role thin E2E checklist decided on #162, expanding the wayfinder map at #156 (resolves #164): admin-only nav links absent, redirected to `/not-authorized` when navigating to `/admin/users`, and Author can edit its own article but not one authored by someone else (exercising `ArticleAuthorizationService.CanEditArticle`'s ownership check).
- New `AuthorAuthFixture` mirrors `AdminAuthFixture`'s pattern: one real Auth0 Universal Login cached as storage state, wired into `E2ETestCollectionDefinition`.
- Surfaced two real bugs against the live Auth0 tenant + dev database:
  1. `AddAuth0WebAppAuthentication`'s cookie scheme defaulted `AccessDeniedPath` to `/Account/AccessDenied` (a route this app never defined). A full page load hitting an `[Authorize]`-gated component is redirected there by ASP.NET Core's own middleware *before* Blazor's `AuthorizeRouteView`/`NotAuthorized` branch (and #183's `RedirectToNotAuthorizedPage`) ever runs. Reconfigured it to `/not-authorized`.
  2. The article-creation success regex `/articles/[a-z0-9-]+$` also matches the still-on-the-create-page URL `/articles/create` itself, so the assertion could pass before the redirect to the new article actually happened. Fixed in both `AdminRoleTests` and the new `AuthorRoleTests`.
