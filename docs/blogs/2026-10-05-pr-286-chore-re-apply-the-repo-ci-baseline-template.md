### What changed

**Apply** (`chore: Apply repo-ci-baseline Template`, the script's output alone; 7 Owned files):

- **pnpm instead of npm and npx** (mpaulosky/dotfiles#66). Without `markdownlint-cli2` installed, `scripts/gate.sh` lints through `pnpm dlx`, and refuses the push if pnpm is missing too. It never falls back to `npx`. The pre-commit hook suggests `pnpm add -g markdownlint-cli2`.
- **A branch behind `origin/main` is refused at push** (mpaulosky/dotfiles#56). The pre-push hook fetches main first and names `git merge origin/main` as the fix. `docs/PROCESS.md` says so.
- **Release posts** (`release_post.py` and its tests):
  - Untrusted Markdown is neutralized in each release post and in the README and blog tables (mpaulosky/dotfiles#51, #53). This covers the PR title and body, the AI summary, commit subjects and file names: raw HTML outside code, `javascript:`/`vbscript:`/`data:` link destinations (including obfuscated forms), kramdown attribute lists, and Liquid (each post is wrapped in <code>&#123;&#37; raw &#37;&#125;</code>). One visible change: <code>&#60;details&#62;</code>/<code>&#60;summary&#62;</code> in a PR description now shows as text.
  - README link rebasing leaves code alone (mpaulosky/dotfiles#54), and an oversized character reference can no longer stop a release (mpaulosky/dotfiles#55).
  - A PR title can't close the blog index row's link early, and only a real footnote definition is exempt from link checks (mpaulosky/dotfiles#59).
  - Code spans pair only within a paragraph (mpaulosky/dotfiles#63).
  - Code stays exactly as written: comments and links inside code spans, tabs, and blank lines in fences are kept (mpaulosky/dotfiles#64).
- **`.gitignore`** ignores local SDK and NuGet caches (`.dotnet/`, `.nuget/`), dotCover reports (`docs/coverage/`), and `.images/` and `.junie/` (mpaulosky/dotfiles#67, moved into the Template from mpaulosky/Articles#284). Nothing tracked is affected.

**Adapt:** none. Articles' own `.gitignore` lines from #284 moved into the Template (mpaulosky/dotfiles#67), so `.gitignore` is unchanged here.
