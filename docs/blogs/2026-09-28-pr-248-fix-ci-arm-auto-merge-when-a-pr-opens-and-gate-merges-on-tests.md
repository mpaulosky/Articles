## fix(ci): Arm auto-merge when a PR opens and gate merges on tests

- **Release tag:** `v0.1.90`
- **Source PR:** [#248](https://github.com/mpaulosky/Articles/pull/248)

### PR description

Closes #239

## Problem

`squad-pr-automerge.yml` only armed GitHub auto-merge once a PR was already `CLEAN`. GitHub refuses to arm auto-merge on a clean PR ("clean status"), and nothing re-ran the workflow after the Copilot review. So PRs sat `CLEAN` and unmerged until someone merged them by hand.

Arming by hand exposed a second problem: the `main` ruleset only requires **Build Solution**. Auto-merge waits only for required checks, so **#245 merged 8 seconds after its build passed, before any test finished**. The tests happened to pass, but nothing enforced it.

## Changes

- **Arm at open.** The workflow now arms squash auto-merge as soon as a same-repo PR opens, is marked ready or is updated, and the ruleset decides when it's ready. A PR that is already `CLEAN` is merged directly, pinned to the head SHA that was checked. Drafts, forks, conflicted PRs and already-armed PRs are skipped.
  - The decision logic lives in `scripts/squad/automerge-decision.mjs`, with 11 `node --test` cases. The **Squad Scripts Test** workflow runs them and now also triggers on changes to the auto-merge workflow.
- **`All Tests Passed` gate job** in `squad-ci.yml`. It is always reported: it fails if the build, test discovery or any test job failed or was cancelled, and passes when tests are skipped (Dependabot PRs, which have no secrets). A required check has to be a job like this. `Test Results Summary` is created inside a job that Dependabot PRs skip, so it would never be reported for them and they would block forever.
- Removed the invalid `check_suite` types `requested` and `rerequested`; workflows only get `completed`.
- `CONTRIBUTING.md` now says which checks gate a merge, and that Copilot's review is advisory.

## After merge

Update the `main` ruleset's required status checks to **Build Solution**, **All Tests Passed** and **Analyze (csharp)**. That has to wait until `All Tests Passed` exists on `main`; otherwise every PR would block.

## Validation

- `actionlint` and `yamllint` are clean on the changed workflows. `squad-ci.yml` still has 14 existing shellcheck notes in the `report` step, the same as `main`.
