# chore: Ignore local SDK caches, coverage reports and personal files

- **Release tag:** `v0.1.104`
- **Source PR:** [#284](https://github.com/mpaulosky/Articles/pull/284)

## PR description

### Why

Running the .NET SDK with its home and package cache inside the repo leaves `.dotnet/` and a ~1 GB `.nuget/` package cache in the worktree, and dotCover writes its reports to `docs/coverage/`. Along with personal screenshots in `.images/` and JetBrains Junie agent files in `.junie/`, these show up as untracked in every `git status`, and could be committed by mistake. None of them belong in the repo.

### What changed

- `.gitignore` now ignores `.dotnet/` and `.nuget/` (local SDK state and NuGet package cache), `docs/coverage/` (generated dotCover reports), and `.images/` and `.junie/` (personal screenshots and Junie agent files).

### Verification

- `dotnet build Articles.slnx`: 0 warnings, 0 errors.
- `dotnet test` with `--configuration Release` for each test project: all 659 tests passed (AppHost 38, Architecture 13, Domain 54, Web.E2E 10, Web.Integration 51, Web 343, Web.UI 150).
- With the change in place, `git status --short` no longer lists the five folders.
