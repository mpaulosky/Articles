## fix(scripts): Make squad branch cleanup see remote branches and fail safe

- **Release tag:** `v0.1.87`
- **Source PR:** [#238](https://github.com/mpaulosky/Articles/pull/238)

### PR description

## Summary

Copilot's review of the cleanup rollout PRs (e.g. mpaulosky/Blazor-Server-Template#13) found that `scripts/squad/cleanup-squad-branches.sh` is both ineffective on GitHub and unsafe locally. This fixes it at the source before it is rolled out to other repos.

**Ineffective:** it listed only `refs/heads`, and a fresh Actions checkout has only `main` locally. Every nightly run reported `Merged branches eligible for cleanup (0)`.

**Unsafe for local `--apply`:**
- any matching branch whose tip was already in `main` counted as merged with no PR, including a brand-new, empty worktree branch;
- a failed `gh pr list` counted as "no PR", so a branch with an open PR could be treated as an orphan;
- `--orphan-days -1` made every branch old enough;
- worktree paths with spaces were truncated;
- a failed `git fetch` was ignored.

## Changes

- Evaluate local branches **and** `origin/*`, and delete only the copies that exist.
- "Merged" requires a merged PR whose head contains every tip being deleted. An open PR always skips the branch.
- A branch with no commits of its own and no PR is skipped.
- A failed `gh` query skips the branch. A failed `git fetch` aborts `--apply`; dry runs warn and continue.
- `--orphan-days` is validated, and worktrees are parsed from `--porcelain`.
- Workflow: a manual `apply` runs only from `main`.

## Tests

New `scripts/squad/tests/cleanup-squad-branches.test.sh`, run by the new **Squad Scripts Test** workflow on PRs touching `scripts/squad/`. Each case uses a throwaway clone with a bare `origin`, a stubbed `gh`, and the machine's git config switched off.

- Fixed script: **16/16 pass**.
- The same tests against the previous script: **11 fail**, covering each issue above.
- `shellcheck`, `actionlint` and `yamllint` are clean.

## First-run impact

On GitHub: none today. `origin` has no matching branches, because head branches auto-delete on merge. Locally in the primary checkout, a dry run lists two unpushed, PR-less branches from August as orphans (`chore/domain-refactoring`, `chore/pre-push-main-sync-gate`). The old script listed them too, and `--apply` still won't delete them without `--force-local`.
