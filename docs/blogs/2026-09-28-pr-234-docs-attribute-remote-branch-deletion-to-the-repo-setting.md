## docs: Attribute remote branch deletion to the repo setting

- **Release tag:** `v0.1.85`
- **Source PR:** [#234](https://github.com/mpaulosky/Articles/pull/234)

### PR description

## What changed
The cleanup step in `docs/CONTRIBUTING.md` now:
- says the remote branch is deleted on merge because the repository setting **Automatically delete head branches** is on (`delete_branch_on_merge: true`), not because of the auto-merge workflow
- gives `git push origin --delete <branch>` and `git fetch --prune` for when the branch is still on `origin`

## Why
This follows up the last open review comment on #226. The old wording read as though the workflow deleted branches. If the setting were ever turned off, following the guide would leave stale remote branches.
