## Overview

Version 0.0.6 sets the stage for a major architectural evolution in the Articles project. This release focuses on preparing the domain layer for feature-based organization while resolving critical infrastructure issues.

## What's New

### Domain Architecture Migration

- **PR #14**: Migrated domain entities to feature-based architecture
  - Restructured domain entities into feature-centric folders
  - Prepared for vertical slice architecture
  - Improved domain model organization
  - Enhanced separation of concerns

### Infrastructure Improvements

- **PR #13**: Resolved Redis and web app issues
  - Fixed Redis connection configuration in AppHost
  - Corrected health check registration
  - Resolved web application startup issues
  - Improved Aspire orchestration reliability

## Technical Details

### Feature-Based Organization

The domain refactoring introduces a new organizational pattern:

**Before (Layer-First)**:
```
Domain/
  Entities/
    Article.cs
    Category.cs
    Tag.cs
```

**After (Feature-First)**:
```
Domain/
  Articles/
    Article.cs
    ArticleId.cs
    ArticleStatus.cs
  Categories/
    Category.cs
    CategoryId.cs
```

### Benefits of Feature-Based Organization

- **Cohesion**: Related code lives together
- **Discoverability**: Easy to find all code for a feature
- **Maintainability**: Changes are localized to feature folders
- **Scalability**: Adding features doesn't clutter shared folders
- **Bounded Contexts**: Natural alignment with DDD concepts

### Redis Configuration Fixes

Resolved issues with:

- Redis connection string configuration in Aspire AppHost
- Health check registration for Redis services
- Resource dependency ordering in AppHost
- Connection pooling and timeout settings

## Impact

This release enables:

- **Architectural Evolution**: Smooth transition to vertical slices
- **Better Organization**: Domain code structured by business capability
- **Infrastructure Stability**: Reliable Redis and web app startup
- **Future Growth**: Foundation for CQRS and MediatR integration

The feature-based structure aligns with:

- **Vertical Slice Architecture**: Feature folders become slices
- **Domain-Driven Design**: Features map to bounded contexts
- **Microservices Readiness**: Features can be extracted as needed

## Migration Impact

This is a preparation release with minimal breaking changes:

- Namespace changes for domain entities
- Import statement updates in tests
- No API or behavior changes
- Existing functionality fully preserved

## What's Next

With the preparation complete, v0.1.0 will:

- Complete the domain refactoring
- Update all test namespaces
- Establish vertical slice patterns
- Document the new architecture
